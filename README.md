# ZBFinancial

แอปบันทึกรายรับรายจ่ายของครอบครัว สร้างด้วย **Google Apps Script** เป็นเว็บแอป และใช้ **Google Sheet** เป็นฐานข้อมูล
ข้อมูลทุกตัวเลขอยู่ในชีตของคุณเอง เปิดตรวจสอบหรือย้อนดูประวัติเวอร์ชันได้ตลอด

หน้าตาเป็นแบบ **Ledger** ที่อนุมัติแล้ว: พื้นขาว-เทา สีน้ำเงินเป็นสีหลัก รายรับสีเขียวอมฟ้า รายจ่ายสีส้ม
ใช้ได้ทุกขนาดจอ บนมือถือเมนูย่อเป็นแถบแท็บด้านล่าง และฟอร์มเพิ่ม/แก้ไขทั้งหมดเป็น modal (บนมือถือเป็นแผ่นเลื่อนขึ้นจากล่าง)

## ฟีเจอร์

| โมดูล | จัดการ (เพิ่ม · แก้ไข · ลบ) | หมายเหตุ |
| --- | --- | --- |
| **ผู้ใช้ (User)** | เพิ่มผู้ใช้ด้วยอีเมล Google, แก้ชื่อ/บทบาท, นำออก | ผู้ใช้เป็นเจ้าของรายการ มีบทบาท ผู้ดูแล / สมาชิก / ดูอย่างเดียว |
| **ครอบครัว (Family)** | สร้าง, เปลี่ยนชื่อ, เพิ่มสมาชิกจากครอบครัวอื่น, ลบ | หนึ่งครอบครัวมีหลายผู้ใช้ และผู้ใช้อยู่ได้หลายครอบครัว สลับได้จากปุ่มมุมขวาบน |
| **รายการ (Item)** | บันทึกรายรับ/รายจ่ายแต่ละครั้ง | ชื่อ จำนวนเงิน หมวดหมู่ เจ้าของ วันที่ **สถานะ** กรองตามสถานะได้ และเปลี่ยนสถานะได้จากปุ่ม "สถานะ" ในแถวรายการ |
| **ประเภท (Type)** | เพิ่ม, แก้ไข, ลบ | แต่ละประเภทเป็น **Expense** (ลดยอดคงเหลือ) หรือ **Income** (เพิ่มยอดคงเหลือ) |
| **หมวดหมู่ (Category)** | เพิ่ม, แก้ไข, ลบ | อยู่ใต้ประเภท ลบหมวดที่มีรายการได้โดยย้ายรายการไปหมวดอื่นก่อน |
| **สถานะ (Status)** | เพิ่ม, แก้ไข, ลบ | แยกตามครอบครัว เริ่มต้นมี รอดำเนินการ / ชำระแล้ว / ยกเลิก แต่ละสถานะตั้งได้ว่า **นับรวม** ในภาพรวมหรือไม่ ลบสถานะที่มีรายการได้โดยย้ายรายการไปสถานะอื่นก่อน |
| **ภาพรวม (Dashboard)** | ดูอย่างเดียว | รายรับ รายจ่าย คงเหลือ, รายจ่ายตามหมวด, ตามคน, แนวโน้ม 6 เดือน, รายการล่าสุด, เลื่อนดูย้อนหลังรายเดือน และบอกว่านับสถานะไหนบ้าง ไม่รวมกี่รายการ |

### สถานะของรายการ

* รายการใหม่เริ่มที่สถานะแรกที่ "นับรวม" (ค่าเริ่มต้นคือ **ชำระแล้ว**) ตรงกับวิธีใช้เดิมที่บันทึกเมื่อเกิดขึ้นจริง
* สถานะที่ **ไม่นับรวม** (ค่าเริ่มต้นคือ รอดำเนินการ และ ยกเลิก) ยังอยู่ในรายการ แต่ไม่ถูกบวกในรายรับ รายจ่าย คงเหลือ กราฟ ยอดต่อคน และยอดคงเหลือของครอบครัว ตัวเลขในรายการจะขีดฆ่าและป้ายสถานะเป็นเส้นประ
* ภาพรวมบอกเสมอว่า "ยอดสรุปนับเฉพาะรายการที่สถานะ ชำระแล้ว · ไม่รวม 2 รายการในเดือนนี้ (รอดำเนินการ 1, ยกเลิก 1) รายจ่าย 3,799 บาท" จะได้ไม่สงสัยว่าตัวเลขหายไปไหน
* เปลี่ยนว่าสถานะไหนนับรวมมีผลย้อนหลังกับทุกรายการที่ใช้สถานะนั้นทันที ต้องเหลือสถานะที่นับรวมอย่างน้อย 1 สถานะ และครอบครัวต้องมีอย่างน้อย 1 สถานะ ครอบครัวหนึ่งมีได้ไม่เกิน 12 สถานะ
* รายการที่ช่องสถานะในชีตว่างหรืออ้างถึงสถานะที่ถูกลบ จะถือว่าเป็นสถานะเริ่มต้นของครอบครัว (นับรวม) ไม่หายไปจากยอด

แอปสร้าง **Workbook และทุกแท็บพร้อมหัวคอลัมน์ให้เอง** (ฟังก์ชัน `setup()` หรือเปิดแอปครั้งแรก) ไม่ต้องเตรียมชีตล่วงหน้า

## เริ่มใช้งาน

ต้องมีบัญชี Google และ Node.js 20+ (ถ้าใช้ `clasp`)

### วิธี A: ผ่าน clasp

```bash
npm install -g @google/clasp
clasp login
clasp create --type standalone --title ZBFinancial --rootDir src   # หรือ copy .clasp.json.example เป็น .clasp.json แล้วใส่ scriptId
clasp push
clasp open
```

### วิธี B: วางในเว็บ Apps Script

เปิด <https://script.google.com> สร้างโปรเจกต์ใหม่ แล้วสร้างไฟล์ให้ตรงกับโฟลเดอร์ `src/` (ไฟล์ `.gs` เป็น Script, ไฟล์ `.html` เป็น HTML) และตั้ง `appsscript.json` ให้เหมือนกัน
(เปิด Project Settings > Show "appsscript.json" manifest file) ถ้าสร้างโปรเจกต์จากเมนู Extensions > Apps Script ของชีตที่มีอยู่ แอปจะใช้ชีตนั้นเป็นฐานข้อมูลเลย

### ขั้นตอนที่เหมือนกัน

1. ในตัวแก้ไข Apps Script เลือกฟังก์ชัน **`setup`** แล้วกด Run (อนุญาตสิทธิ์ครั้งแรก)
   ระบบจะสร้าง Google Sheet ชื่อ "ZBFinancial · ข้อมูลครอบครัว" พร้อมแท็บ `Users, Families, Memberships, Types, Categories, Statuses, Items`
   จดจำไฟล์ไว้ใน Script Properties (`SPREADSHEET_ID`) และลงทะเบียนอีเมลของคุณเป็น **ผู้ดูแลคนแรก** พร้อมครอบครัวเริ่มต้น ประเภท และหมวดหมู่พื้นฐาน
   ลิงก์ชีตอยู่ใน Execution log
2. **Deploy > New deployment > Web app**
   * Execute as: **User accessing the web app**
   * Who has access: **Anyone with Google account**
3. แชร์ Google Sheet ให้อีเมลของสมาชิกทุกคนด้วยสิทธิ์ **Editor** (ดูเหตุผลด้านล่าง)
4. เปิดลิงก์เว็บแอป เข้าด้วยบัญชีของคุณ ไปที่เมนู **ผู้ใช้** แล้วเพิ่มอีเมลคนในบ้าน คนที่ยังไม่ถูกเพิ่มจะเห็นหน้า "ยังไม่ได้รับเชิญเข้าครอบครัว"

### ทำไมต้อง "User accessing the web app"

แอปรู้ว่าใครเข้าใช้จากอีเมล Google ของผู้เปิดหน้า (`Session.getActiveUser()`)
ถ้าตั้ง Execute as: **Me** บัญชี gmail.com ทั่วไปจะอ่านอีเมลผู้ใช้ไม่ได้ ระบบจึงแยกคนไม่ได้
ผลที่ตามมาคือสมาชิกต้องมีสิทธิ์เข้าถึงไฟล์ชีตด้วย ซึ่งตรงกับจุดเด่นที่ข้อมูลโปร่งใสและตรวจสอบได้ แต่ **คนที่มีสิทธิ์แก้ชีตเปิดดูและแก้ข้อมูลของทุกครอบครัวในไฟล์เดียวกันได้โดยตรง**
ถ้ามีหลายครอบครัวที่ไม่ไว้ใจกัน ให้ติดตั้งแยกกันครอบครัวละหนึ่งชุด
องค์กร Google Workspace ที่ผู้ใช้อยู่โดเมนเดียวกันสามารถใช้ Execute as: Me ได้ และให้เฉพาะเจ้าของเป็นผู้เข้าถึงไฟล์

ถ้ามีคนเปิดแอปโดยที่ระบบยืนยันอีเมลไม่ได้ จะเห็นข้อความอธิบายว่า "ยังยืนยันตัวตนไม่ได้" และไม่มีการให้สิทธิ์ใด ๆ โดยอัตโนมัติ

## แก้ปัญหา: เปิดแอปไม่ได้

| สิ่งที่เห็น | สาเหตุที่พบบ่อย | วิธีแก้ |
|---|---|---|
| Google ไดรฟ์: "ขออภัย ไม่สามารถเปิดไฟล์ได้ในเวลานี้" / "Sorry, unable to open the file at present" และ URL มี `/macros/u/1/` | ล็อกอิน Google หลายบัญชีในเบราว์เซอร์เดียวกัน Google เลือกบัญชีลำดับที่สองมาเปิด | เปิดหน้าต่างส่วนตัว (Incognito / Private) ล็อกอินบัญชีเดียวที่ใช้ deploy แล้ววางลิงก์ `https://script.google.com/macros/s/<รหัส>/exec` ที่ไม่มี `/u/N/` |

| หน้าขาว หรือโหลดค้างหลังล็อกอิน | เบราว์เซอร์บล็อกคุกกี้ของเว็บอื่น (เช่น Brave Shields) | ปิด Shields ของ `script.google.com` หรือลองใช้ Chrome / Safari |
| "เปิดหน้าแอปไม่สำเร็จ" พร้อมข้อความสีเทา | ไฟล์ในโปรเจกต์ Apps Script ขาด สะกดชื่อผิด หรือยังเป็นโค้ดเก่า | เปิด `…/exec?diag=1` ดูข้อที่ ✗ แล้วทำตามข้อความใต้ข้อนั้น |
| "ยังยืนยันตัวตนไม่ได้" | deploy เป็น Execute as: **Me** | Deploy > Manage deployments > ดินสอ > Execute as: **User accessing the web app** > Version: **New version** > Deploy |
| "ยังไม่ได้รับเชิญเข้าครอบครัว" | อีเมลที่เปิดไม่อยู่ในแท็บ Users | ให้ผู้ดูแลเพิ่มอีเมลนั้นในเมนู ผู้ใช้ |
| "เปิด Google Sheet ไม่ได้" | บัญชีนั้นไม่มีสิทธิ์ Editor ของไฟล์ชีต | เจ้าของแชร์ชีตให้อีเมลนั้นเป็น Editor |
| แก้โค้ดแล้วแต่หน้าเว็บยังเหมือนเดิม | deployment ยังชี้ version เก่า | Deploy > Manage deployments > ดินสอ > Version: **New version** > Deploy (ลิงก์เดิมใช้ต่อได้) |

### ตรวจระบบเอง

* **ในตัวแก้ไข Apps Script**: เลือกฟังก์ชัน **`diagnose`** กด Run แล้วดูผลใน Execution log ทุกบรรทัดขึ้นต้นด้วย `[ผ่าน]` หรือ `[ไม่ผ่าน]` พร้อมวิธีแก้
* **ในเบราว์เซอร์**: เปิดลิงก์เว็บแอปแล้วต่อท้าย `?diag=1` เช่น `https://script.google.com/macros/s/<รหัส>/exec?diag=1`
  หน้านี้ตรวจ 6 ไฟล์หน้าเว็บ อีเมลที่ระบบเห็น การเปิด Google Sheet หัวคอลัมน์ทุกแท็บ และการลงทะเบียนใน Users
  โดยไม่แก้ไขข้อมูลใด ๆ และไม่แสดงข้อมูลรายการของครอบครัว

## โครงสร้างข้อมูล (Google Sheet)

แถวแรกของทุกแท็บคือหัวคอลัมน์ **อย่าแก้หรือสลับลำดับ** (ระบบจะแจ้งชัดเจนถ้าไม่ตรง) เพิ่มคอลัมน์ทางขวาเองได้ ระบบจะไม่แตะ

| แท็บ | คอลัมน์ |
| --- | --- |
| `Users` | id, email, name, createdAt, updatedAt |
| `Families` | id, name, createdAt, updatedAt |
| `Memberships` | id, familyId, userId, role (`admin` / `member` / `viewer`), createdAt |
| `Types` | id, familyId, name, kind (`EXPENSE` / `INCOME`), createdAt, updatedAt |
| `Categories` | id, familyId, typeId, name, createdAt, updatedAt |
| `Statuses` | id, familyId, name, counted (`TRUE` / `FALSE` นับรวมในภาพรวมหรือไม่), createdAt, updatedAt |
| `Items` | id, familyId, categoryId, ownerId, name, amount, date (`yyyy-MM-dd`), createdAt, updatedAt, statusId |

* จำนวนเงินเก็บเป็นบวกเสมอ ประเภทของรายการเป็นตัวกำหนดว่าบวกหรือลบ (ประเภทของรายการคือประเภทของหมวดหมู่ จึงไม่มีทางขัดกันเอง)
* ข้อความทุกช่องเขียนด้วยรูปแบบ plain text ชื่อรายการที่ขึ้นต้นด้วย `=` หรือ `+` จึงไม่ถูกตีความเป็นสูตร
* ทุกการเขียนอยู่ใต้ `LockService` กันสองคนบันทึกพร้อมกัน

### อัปเดตจากเวอร์ชันที่ยังไม่มีสถานะ

ข้อมูลเดิมไม่ต้องแก้มือ: หลัง `clasp push` และ Deploy เป็น version ใหม่ (หรือกด Run `setup` หนึ่งครั้ง) แอปจะอัปเกรดชีตเองตอนเปิดครั้งแรก

1. สร้างแท็บ `Statuses` และใส่สถานะเริ่มต้นให้ **ทุกครอบครัว**
2. เพิ่มคอลัมน์ `statusId` ท้ายแท็บ `Items` และตั้งทุกรายการเดิมเป็น **ชำระแล้ว** ของครอบครัวนั้น

รายการเดิมจึงเป็น "นับรวม" ทั้งหมด ตัวเลขในภาพรวมเท่าเดิมทุกตัว ทำซ้ำได้ปลอดภัย (ไม่สร้างสถานะซ้ำ ไม่ทับข้อมูลที่ตั้งไว้แล้ว) ถ้าเคยเพิ่มคอลัมน์ของตัวเองไว้ที่คอลัมน์ที่ 10 ของแท็บ `Items` แอปจะไม่เขียนทับ แต่แจ้งให้ย้ายคอลัมน์นั้นไปทางขวาก่อน
หน้า `?diag=1` จะแสดงว่า "ยังเป็นรูปแบบเดิม ระบบจะอัปเกรดให้เอง" โดยไม่แก้ข้อมูล

## สิทธิ์

| | ผู้ดูแล | สมาชิก | ดูอย่างเดียว |
| --- | :-: | :-: | :-: |
| ดูทุกอย่างในครอบครัว | ✓ | ✓ | ✓ |
| บันทึก/แก้/ลบรายการ | ของทุกคน | เฉพาะของตัวเอง | – |
| จัดการประเภท หมวดหมู่ สถานะ | ✓ | – | – |
| เปลี่ยนสถานะของรายการ | ของทุกคน | เฉพาะของตัวเอง | – |
| เพิ่ม/นำผู้ใช้ออก เปลี่ยนบทบาท | ✓ | – | – |
| เปลี่ยนชื่อ/ลบครอบครัว | ✓ | – | – |
| สร้างครอบครัวใหม่ | ✓ | ✓ | ✓ |

ทุกคำสั่งตรวจสิทธิ์ที่ฝั่งเซิร์ฟเวอร์ ปุ่มที่ซ่อนไว้ในหน้าจอเป็นเพียงความสะดวก ครอบครัวหนึ่งมีผู้ดูแลอย่างน้อย 1 คนเสมอ

ไม่มีอะไรหายไปเงียบ ๆ: ลบหมวดหรือสถานะที่มีรายการต้องเลือกปลายทาง, นำผู้ใช้ที่เป็นเจ้าของรายการออกต้องเลือกผู้รับช่วงต่อ,
ลบครอบครัวที่มีข้อมูลต้องยืนยันพร้อมจำนวนที่จะลบ, เปลี่ยนรายรับ/รายจ่ายของประเภทที่มีรายการแล้วไม่ได้

| **Ethos** (ความน่าเชื่อถือ) | บอกที่มาของตัวเลขทุกหน้า ("ดึงจาก Google Sheet ของครอบครัว · โหลดเมื่อ 04:30 น.") พร้อมลิงก์เปิดชีตดิบ, บอกว่ายอดสรุปนับสถานะไหนและข้ามรายการไหนไปบ้าง, เทียบเดือนที่ยังไม่จบกับช่วงวันเดียวกันของเดือนก่อน ไม่เทียบกับทั้งเดือนให้ดูดีเกินจริง, บอกตรง ๆ เมื่อทำไม่ได้และเพราะอะไร |
| **Pathos** (อารมณ์) | ข้อความให้กำลังใจเมื่อรายจ่ายลดลง ("ทำได้ดีมาก") ไม่ตำหนิเมื่อรายจ่ายเกินรายรับ แต่ชวนวางแผนเดือนถัดไป, หน้าว่างชวนเริ่มบันทึกรายการแรก, ข้อความผิดพลาดบอกว่าต้องทำอะไรต่อและย้ำว่าข้อมูลยังปลอดภัย |
| **Logos** (เหตุผล) | ทุกข้อสรุปมีตัวเลขรองรับ (ร้อยละของรายรับ ส่วนต่างจากเดือนก่อน ส่วนแบ่งแต่ละหมวด), ข้อความ validation ระบุช่องที่ผิดและวิธีแก้ |

## ใช้ได้ทุกขนาดจอ

เลย์เอาต์ตามความกว้างจริง ไม่ผูกกับรุ่นเครื่อง: การ์ดสรุปใช้ grid แบบ auto-fit, รายการ wrap ตามพื้นที่, ตารางไม่มีแถบเลื่อนข้าง
ที่ความกว้างไม่เกิน 720px เมนูบนสุดซ่อนและย้ายไปเป็นแถบแท็บด้านล่าง (ภาพรวม · รายการ · ปุ่ม + · หมวดหมู่ · เพิ่มเติม) ปุ่มและช่องกรอกสูงอย่างน้อย 44px, ช่องกรอกใช้ตัวอักษร 16px กัน iOS ซูมเอง, รองรับ safe area ของ iPhone
ทดสอบด้วยเบราว์เซอร์จริงตั้งแต่ 320 ถึง 1920px (`node dev/e2e.js`)

## พัฒนาต่อ

```bash
npm test          # unit test ของโค้ด Apps Script ทั้งหมด รันบน Node ด้วย Sheet จำลอง
npm run dev       # เปิดแอปจริงบนเครื่อง http://localhost:5173/?as=por@gmail.com (ข้อมูลตัวอย่างบ้านสุขใจ)
node dev/e2e.js   # เดินใช้งานจริงในเบราว์เซอร์ + ตรวจ responsive + เก็บภาพไว้ที่ dev/.screens/ (ต้องมี Playwright)
```

โครงสร้างโค้ด

```
src/
  appsscript.json        manifest (เขตเวลา Asia/Bangkok, สิทธิ์, web app)
  Code.gs                doGet, api, setup   (ฟังก์ชันเดียวที่เรียกจากภายนอกได้)
  Api.gs                 ตัวกระจายคำสั่ง api(action, payload) พร้อม lock และจัดรูปแบบ error
  Auth.gs                ระบุตัวผู้ใช้ + สิทธิ์ (Auth, Perm)
  Db.gs                  Google Sheet เป็นฐานข้อมูล: สร้างแท็บ ตรวจหัวคอลัมน์ อ่าน/เขียน/ลบทีละหลายแถว
  Users.gs Families.gs Catalog.gs Statuses.gs Items.gs   กติกาของแต่ละโมดูล
  Dashboard.gs Views.gs  ตัวเลขภาพรวมและ payload เดียวต่อหนึ่งหน้าจอ
  Index.html Styles.html Js*.html            หน้าเว็บ (HTML + CSS + JS ล้วน ไม่พึ่ง framework)
dev/    Sheet จำลอง เซิร์ฟเวอร์พรีวิว ข้อมูลตัวอย่าง และสคริปต์ e2e
tests/  unit test (node:test)
```

ไฟล์ `.gs` ใช้แค่ `var` และ object (namespace) ระดับบนสุด ลำดับการโหลดจึงไม่มีผล และฟังก์ชันที่เรียกจากเบราว์เซอร์ได้มีเพียง `api`

## ข้อจำกัดที่ควรรู้

* หนึ่ง action ใช้เวลาราว 1-2 วินาที (Apps Script + Sheets) หน้าจอจึงแสดงแถบโหลดด้านบนระหว่างรอ
* ออกแบบสำหรับครอบครัว (ข้อมูลหลักพันถึงหมื่นแถว) ถ้าข้อมูลโตมากกว่านั้นควรย้ายไปฐานข้อมูลจริง
* สกุลเงินบาทเท่านั้น ยังไม่มีงบประมาณ รายการประจำ แนบใบเสร็จ หรือส่งออกไฟล์ (นอกขอบเขตเฟสแรก)
